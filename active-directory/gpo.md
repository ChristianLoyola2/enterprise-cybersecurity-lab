# Active Directory Group Policies (GPO)

## Overview

Group Policy Objects (GPOs) were used in the laboratory to centrally manage security settings and configuration policies for the Windows environment.

The objective was to apply consistent security controls to domain-joined systems and improve auditing and monitoring capabilities.

## Configured GPOs

The laboratory includes the following policies:

- Default Domain Policy
- GPO-SEGURIDAD-EQUIPOS
- GPO-AUDITORIA-DOMINIO

## Security Policies

### Password Policy

The domain password policy was configured with the following controls:

| Control | Configuration |
|---|---|
| Minimum password length | 12 characters |
| Password history | 24 passwords |
| Account lockout threshold | 5 failed attempts |

These controls were configured to strengthen authentication security and reduce the risk associated with weak or repeatedly reused passwords.

## Account Lockout

An account lockout policy was configured to help protect against repeated authentication attempts.

The laboratory uses a threshold of:

**5 failed authentication attempts**

This configuration was used to generate and investigate authentication-related security events.

## Security Auditing

Advanced auditing policies were configured to increase visibility into security-relevant activity on Windows systems.

The laboratory was used to monitor events related to:

- User authentication
- Failed authentication
- User creation
- Group membership changes
- Object access
- Account lockout
- PowerShell activity

## PowerShell Logging

PowerShell logging was enabled to improve visibility into script execution and administrative activity.

The laboratory includes monitoring of PowerShell-related events such as:

- Event ID 4103
- Event ID 4104

These events can be collected and analyzed through the security monitoring infrastructure.
